# 现有资源下的 UI / UX 与读取优化 · 2026-10-18

本轮以 GitHub 主存储、Pages 基础版、Next.js 进阶版为前提，不新增依赖、数据库、付费服务或部署配置。保留暖纸 / 深墨、朱红强调和光影边界。

## 已实现

- 私仓照片真正按可见范围读取：`PhotoImage` 观察稳定图片槽，距视口 160px 开始读取；滚动弹层也适用。原来的原生 `loading=lazy` 无法阻止预先生成 Blob URL 的请求。显式 eager 图片立即读取；不支持 IntersectionObserver 时回退读取。观察器离开组件时释放，异步结果不回写已卸载组件。
- 未进入读取范围的卡片保持原尺寸光影占位，不运行加载转圈；错误与原位重试保留。图片解码继续异步，原有尺寸 / 裁切和减少动态效果规则不变。
- 基础版照片读取最多 3 路完整操作并行；同一源仍共享已有 Promise；失败释放槽位并允许重试。断开连接中止正在请求，队列开始时仍先检查连接关闭状态，不再发出网络请求。
- GitHub 只读快照不再请求写入才需要的 base tree：日志读取 4 → 3 个请求；单张未缓存照片读取 5 → 4 个请求。仍逐次验证私仓、固定 commit 索引、日志 / 行 owner、移除与发布状态；写入仍取得 base tree 并遵守原有非强制更新 / 重试 / 租约。没有跨用户或跨请求私人缓存。
- 照片搜索优先更新输入，再推迟刷新列表；计数 / 当前队列与实际显示结果一致。无关键词时跳过整库文本规范化；先检查标记 / 笔记 / 相册条件，照片库与相册共用这一优化。
- 地图搜索关闭时不计算候选，输入使用延迟值。照片拼图生成按“是否展示笔记”布尔阈值复用，不再随每一帧连续缩放重建 SVG；边界 / 照片 / 记录变化照常重建。表单小地图投影只在地理集合变化时重算。

## 后续资源优先级

先观察实际个人图库规模，再决定是否增加派生缩略图、服务端分页或有上限的 Blob 缓存。当前仍读取已去元数据的完整 JPEG，既有 512KiB 索引 / 单图 3MiB 与 Git 历史增长边界不变。可选 Redis 继续只承担已实现的写入协调；本轮不新增队列消费者、不缓存私人内容，也不改登录限流方案。

发布沿用 main → GitHub Checks / Pages 与 Vercel 自动构建；实际状态按本轮提交 SHA 核对，独立新手验收仓库不自动同步。

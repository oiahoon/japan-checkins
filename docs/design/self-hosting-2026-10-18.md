# 自部署双版本与首次使用验收 · 2026-10-18

## 最新决定：Git基础版只读，服务端进阶版可写

用户后续明确选择基础版尽量通过Git操作，取代前期“基础版也网页上传”的要求。最终基础版隐藏全部写入控件且在适配器拒绝非GET；地图 / 时间线 / 照片 / 相册 / 导出保留。私仓只读Contents token只用于读取。Git导入模板、命令、确认manifest和增量签名已实现；Redis仅有可选方案文档，未实现或部署。

新增153项测试通过，覆盖只读适配器拒绝所有写入、导入提议不生成访问、内容ID幂等、JPEG去EXIF与Git blob SHA、显式确认 / 相册、后续网页编辑不被相同manifest覆盖，以及非法owner / 坐标 / 路径 / 符号链接 / 损坏图片整批失败。本地私仓权限验证与导入命令成功；真实Actions链路结果在最终发布记录补充。

本机320px静态子路径构建已验证：地图操作菜单无管理入口，照片页无添加 / 选择 / 批量管理按钮，仍有照片筛选 / 查看与时间线，地理资料链接带正确子路径。

以下“前期可写基础版”浏览器上传验收是历史设计验证，不能作为最终基础版网页上传能力的宣传。进阶版仍支持这些网页交互。

## 前期产品合同（已由顶部最新决定更新）

每位用户 fork（或 clone 后 push）到自己的源码仓库，部署到自己的 Pages / 服务端，再连接自己的 private 数据仓库。不共用作者的正式站点、照片、访问权限或部署凭据。Vercel 可选，不引入数据库。

前期方案中基础版只有公开应用壳和地理资料；Actions 构建 / 发布代码，浏览器解析 EXIF 并通过 GitHub REST API 上传与保存。私人访问由 GitHub token 权限验证，不能用前端共享密码替代。必须启用 Pages 并进行一次仓库 / fine-grained token 配置；刷新需要重新输入，不能宣传成零配置一键私人网站。照片不会经过 Actions、Pages 或作者服务。进阶版保留服务端密码 / 访客与可选发布；标准 Next.js 同时支持 Vercel 与持久单机 Node。

## 实现

- Pages 子路径构建、私仓 BrowserJournal 适配器、共用 Travel UI、私有 Blob 查看器 / 拼图 / 导出、断开取消请求和撤销 URL。
- GitHubStore 继续核对 private 与逐行 owner，原子 tree / commit / 非强推 ref，保持并发和重试幂等。只把 Buffer 编码替换成浏览器兼容的 UTF-8 / base64。
- 令牌只在页内存，不进地址、持久存储、构建环境或 Actions。静态 CSP 限制脚本同源、GitHub API 连接；静态产物扫描私人目录和凭据。
- setup 交互初始化、目标 env 快照、生成密码仅本机600权限、保留已有配置；doctor 与认证 / 同源 `/setup` 只读检查。
- Vercel 可信生产域名默认值；单机每分钟全站5个持久原子槽位，跨进程 / 重启，故障拒绝登录。Vercel仍要求真实配置WAF；未自动宣称已开启。
- 登录页对缺失限流配置给出明确状态，移动端断开按钮有可访问名称；照片异步加载与查看器等待状态、公共资料子路径已检查。

新建单独 private QA 数据仓库，只使用合成JPEG（固定虚拟地点 / 2020-01-02日期），不读取或改写既有私人照片和记录。测试配置和证据在工作站临时目录，不进入源码或云部署。测试凭据没有提交或复制到任何生产环境。

1. 从无 `.env.local` 的独立源码副本安装依赖并运行setup；生成独立密码和会话密钥，仓库remote doctor通过。
2. production build / start，经本机HTTPS代理、显式校验测试证书，验证密码登录与Secure `__Host-` 会话。

4. 未登录记录 / 照片 / setup 拒绝；异源登录拒绝；viewer不能写入或查看部署检查。
5. Pages式静态构建挂载 `/japan-checkins/`，实际浏览器连接QA私仓、从文件选择器上传、解析拍摄日期、选福冈建议补齐日本 / 福岡県 / 福岡市、保存笔记 / 地图标记、加入新旅行记录。

首次浏览器上传遇到GitHub超时，没有产生记录；界面保留照片并可重试，之后真实写入成功。新错误提示区分超时 / 断网；没有把外部网络稳定性当成功能已保证。另一次独立Node适配器网络试验超时，不替代上述已成功浏览器链路。

# 手机与受限响应验收 · 2026-10-18

## 范围与方法

沿用 5b1768c 为基线，检查照片列表 / 站内查看器、地图缩放 / 拖拽 / 层级、地图—时间线—照片往返。使用仓库外 `/tmp/travel-mobile-weak-20261018` 的生产模式 Vite 构建与同一套合成资料；没有使用真实私人照片、修改日志或新增服务。原生 Chrome 性能工具因已运行配置进程无法连接；未终止用户浏览器或修改系统代理。

测试 HTTP 服务只监听 loopback：照片和 JSON 每个响应限速 48KiB/s，头部延迟 400ms，中国行政名称目录单独延迟 10 秒；文本使用 gzip，JS / CSS / HTML 不限速。合成 JPEG 为 640×480、161976 字节，transport 共享源 Promise、3 路照片读取。这个受控慢响应模型不是完整 3G / 4G 仿真，没有全链路总带宽、CPU 降速、丢包或真机 Safari。

fixture 在应用启动后用 DOM MutationObserver 记录首次列表、首次成功图片与拼图图片数量变化，计时通过可见 QA 标记读取；不是导航耗时、LCP、INP 或 FPS。原对照使用同一份 48 张资料；之后另加合成四川记录检查拼图，不把不同资料混作计时对照。测量是一次对照样本，不作为生产 SLA。

## 发现与修复

1. **无关资料阻塞全部界面。** 旧版等所有初始请求结束才显示照片 / 时间线。现在分别维护记录和核心地图的就绪状态；行政名称目录 / 餐厅资料后台读取，慢目录不阻止已经取得的照片。地图记录未到时显示读取状态，不提前给出“没有到访”的结论；失败仍保留通知与重试。
2. **切页丢失浏览上下文。** 保留已经访问的三个视图，未访问视图仍不挂载。普通导航恢复照片 / 时间线滚动、搜索、筛选、选择与递增显示范围，并保留地图相机、边界缓存和拼图。隐藏视图不参与布局 / 辅助功能，每次只有一个 `journal-main`。显式“整理照片”是新的筛选命令，清除旧关键词、开启未标记并回到顶部；重复点击记录的查看地图仍能重新聚焦。
3. **拼图等整批照片才出现。** 改为每张照片取得后增量显示；切离地图停止派发后续拼图任务，返回使用既有 URL。已在进行的照片请求可能完成，不声称所有网络流量立即中止。非日本拼图不再仅因开启开关而加载日本详细城市几何；日本城市搜索 / 编辑等需要它的行为保留。
4. **弱网查看器先露出破图。** 私有 Blob URL 尚未产生时，等待区隐藏未就绪的 img，保留标题和居中加载提示。实际读取完才显示图片；错误及手动重试保留。

保留暖纸 / 深墨、光影边界与现有动画，不改变 EXIF 确认、owner、发布、回收站、写入幂等或认证契约。没有增加私人共享缓存或 Redis 队列。保留视图增加会话内 DOM 占用；仍沿用照片 48 项、时间线 24 项递增显示，不是虚拟列表或无限图库容量验收。

## 发布与后续边界

本轮随 main 提交触发 Checks、clone-and-deploy、GitHub Pages 与 Vercel Production，发布需按对应提交核对。生产核验仅检查入口与未登录私人 API 保护，不在用户真实日志做弱网破坏测试。

真实 iPhone / Safari、低端 CPU、抖动 / 丢包、全链路 LCP / INP / 帧率仍待独立验收。完整 JPEG 在弱网下仍有传输成本，已有预取 / 队列也可能让新选择等待；后续应结合实际图库评估缩略图、前台请求优先级和精细取消。日本详细城市整包仍较大，极慢连接可能触发现有 15 秒失败 / 重试；本轮没有改数据源、分片或承诺所有层级即时出现。

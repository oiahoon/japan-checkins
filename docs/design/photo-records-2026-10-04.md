# 照片与旅行记录 · 2026-10-04

## 产品合同

照片是一份独立记忆；旅行记录是用户主动建立的相册；文字可以单独存在。照片只能归属一个旅行记录，不根据相近时间、地点自动合并。相册日期、标题和笔记与单张地点 / 日期 / 笔记分别保存。加入相册不等于确认去过某处；原有“保存并标记地图”仍承担地图确认。

| 入口 | 操作 | 结果 |
| --- | --- | --- |
| 照片卡下方 | 加入旅行记录 | 新建相册或选择已有相册，保留该照片信息 |
| 照片库选择模式 | 单选 / 批量，加入记录 | 已归属照片不能抢占；前 100 张可批量选择 |
| 照片库筛选 | 所有 / 未归属 / 某记录，叠加未标记与无笔记 | 批量管理沿用记录筛选 |
| 记录内添加照片 | 选择未加入别的记录的照片 | 当前相册和其他相册成员均不在待加入列表 |
| 记录内选择成员 | 从记录移除 | 保留照片文件、单张信息与确认过的地图落点 |
| 记录信息 | 编辑标题 / 日期 / 笔记 | 只更新相册正文；文字记忆需要非空正文 |
| 记录 / 照片回收站 | 移除 / 恢复 | 父级移除时隐藏成员，恢复父级不恢复单独删除的照片 |
| 时间线 | 相册 / 单张 / 文字 | 同一照片仅出现一次；未确认拍摄日期明确标记 |

## 表现与层次

沿用现有宋体标题、暖纸 / 深墨表面、朱红强调与共享轻凸 / 凹陷光影。相册先看正文与图片，编辑折叠；添加照片和移出照片是两个显式模式。照片点击选择，选中态为朱红圆点；查看与补充单独保留，退出编辑 / 查看回到父记录。手机记录全屏并固定底部动作，390px 两列照片，768px 三列，桌面四列。只读相册去除选择、编辑、添加、移除，保留图片查看。

时间线仍按月 / 日排列。相册使用封面、照片计数和其他图片缩略图；独立照片用紧凑图文；文字用凹陷页，无空封面占位。已保存旧美食类别、已吃过、探索深度继续显示。未确认日期建议只参与阅读顺序，无落点操作。新相册缺少日期时归入待补充，不用上传时间猜日期。

新增选择 / 记录筛选令照片库操作换行；批量管理在 320px 把记录筛选放独立一行，避免全选按钮被挤成竖排。动画沿用时间线出现动效和已有控件反馈，尊重 reduced-motion。

## 存储、兼容与隐私

版本 1 私有 index 添加 entries 和 photo.entry。photo.checkin 仍是地图落点；entry 是相册归属。entry 缺省兼容旧相册，显式 null 解除归属。旧多照片到访中编辑单张造成落点拆分时，把原相册归属显式保存。服务端先验证全部成员冲突 / 所有权 / 父级状态再原子提交，失败不部分加入；稳定 ID 支持丢响应重试。不要用旧版本应用覆盖已写入新字段的 index；恢复数据应从私有仓库 Git 历史恢复完整索引。

新相册和文字记忆目前仅私人访问，未实现公开相册 / 分享链接。加入关联撤回旧到访公开状态，公开投影过滤新相册成员和落点。旧 Sites 适配器不支持新操作，原迁移和私人资源没有更改。现有 JPEG 元数据剥离、EXIF 提案、相机 metadata、所有权与地理边界校验持续由原测试覆盖。

## 验收证据

使用临时 /entries-qa 路由和合成主人 / 地点 / 日期，数据写入该页 sessionStorage，调用与生产同一 mutateEntry / manageItems / chronicleItems。预览照片为项目原型已有 Picsum seed 示例，非用户旅行。该路由已在正式提交前移除；示例图片、真实照片 / EXIF、账号凭证不进入 Git。

- 118 个 Node 合成测试：关联唯一性 / 冲突原子性、稳定 ID 重试、旧数据 reload、文字校验、地图确认独立、旧相册编辑保留归属、回收恢复、父级隐藏、只读 / Origin / owner、公开投影与 blob 拒绝。
- 手机实操：01 / 02 创建相册 → 刷新与记录筛选 → 单张移出 → 记录内添加三个未归属成员 → 合成保存失败保留 2 张选择 → 重试成功 → 照片仍在库；另跑单张 03 加入既有相册并再移出。
- 管理实操：按相册筛出两张 → 移除一张 → 同一筛选回收站出现一张 → 恢复 → 原归属保留。
- 混合阅读：旅行相册、独立照片、文字正文、日期待补充并存；新建文字填写日期成功回填；编辑相册笔记后时间线立即更新。
- 响应式：320px 管理无横向溢出 / 按钮修正，390px 相册与混合时间线，768px 相册折叠编辑，1280px 图文时间线；明暗主题。只读相册无写控件；控制台无 warn / error，无错误遮罩或空白页。

# 可选 ImageKit 私有图片加速

默认从自己的私有 GitHub 仓库读取照片，**不需要注册图床**。本功能只用于服务端进阶版（Vercel / 自有 Node 服务器）；GitHub Pages 基础版保持原有私仓只读方式，不在浏览器放置图床私钥。

## 开启前先了解

Git 继续保存展示 JPEG、缩略图和记录，是唯一事实来源。启用加速代表允许本站将去除元数据的展示图 / 缩略图复制到**自己的 ImageKit 账户**，不传私人笔记、日期、GPS、相机字段或 inbox 原文件。网页上传原文件本来就不会保存；Git 导入的 inbox 原文件仍只在私仓。

ImageKit 只影响读取途径，不影响保存成功与否。上传先完成 Git 原子提交，再在响应后尝试建立私有副本；旧照片在被查看时按需补齐。首次没有副本、服务故障、额度不足、签名失效、跨域失败或配置不完整都会回退 Git。应用不会自动批量搬迁，也没有持久后台队列；不会修改照片信息。主人明确授权后可以进行一次性私有副本补齐，本实例的实际验收见 [旧照片补齐记录](design/imagekit-existing-2026-10-21.md)。

## 最简单的配置方式

1. 注册自己的 [ImageKit 账户](https://imagekit.io/registration/)，选择免费方案即可开始。
2. 在 **Settings → Images → Security → Restrict unsigned image URLs** 选择 **Restrict all requests** 并保存。不要只限制 AI 请求，也不要打开 Restrict unnamed image transformations（本项目不依赖命名变换）。请保持该保护；关闭它可能影响账户内旧副本的私密性。
3. 从 **URL endpoints** 复制默认地址，从 **Developer options → API keys** 获取已有 private key。显示密钥可能需要邮箱验证码；不要复制带星号的掩码，不需要 Roll keys。此服务端集成不需要 public key。
4. 本机运行 `npm run setup`，在图片加速中选择“配置 ImageKit”。私钥输入隐藏；确认已经开启访问限制后输入 `yes`。引导生成的 `.setup/vercel.env` / `.setup/server.env` 包含此可选配置，不要提交或分享。
5. 将配置导入部署平台后重新部署（自有服务器重启）。主人登录 `/setup`，展开“可选：加速照片加载”，点击“验证私有图片加速”。它只上传一个合成色块，检查无签名请求与变换均被拒绝、签名读取字节一致，并尝试删除测试色块。

熟悉环境变量也可以直接填写：

```dotenv
PHOTO_DELIVERY=imagekit
IMAGEKIT_URL_ENDPOINT=https://ik.imagekit.io/YOUR_ACCOUNT
IMAGEKIT_PRIVATE_KEY=YOUR_PRIVATE_KEY
IMAGEKIT_PRIVATE_DELIVERY_CONFIRMED=true
```

这些均为**服务端变量**，不能加 `NEXT_PUBLIC_` 或填入 Pages 构建。密钥至少需要本账户媒体上传 / 读取 / 删除（删除仅用于合成验证色块）；选择受限密钥时请按这些用途授权。第一版只支持标准 `https://ik.imagekit.io/账户`，尚不接受任意自定义域名 / 代理地址，避免误接外部服务。

也可在本机运行 `npm run imagekit:check`：只在该短命诊断进程中验证已有图床配置，上传 / 清理合成色块，不读取旅行照片、不改写 `.env.local`，可在默认 Git 模式下先验收。

普通 `npm run doctor -- --remote` 只检查加速配置格式，仍只读，不向图床发送照片。配置格式正确不等于私有加速已验证；可选项失败不会阻止使用 Git。

## 如何关闭与回退

设置 `PHOTO_DELIVERY=git` 并重新部署 / 重启即可。可以保留密钥以便之后重新启用；删除密钥也会安全回退。Git 中的图片和记录没有改变，不需要迁回或重传。

关闭加速不会自动删除 ImageKit 内的副本。它们应继续保持 private 与全局签名限制；可在确认不再需要时自行管理图床副本，**不要误删 Git 数据仓库**。密钥轮换会产生新的隔离路径，旧副本的清理也是独立维护操作。

## 隐私与访问契约

- 每次签发链接前，服务端仍检查 GitHub 仓库必须为 private、owner、照片 / 所属记录回收状态以及明确发布规则。读图链接不包含 Git token、blob SHA、地点、笔记或记录 ID。
- 开启前及实例内每 5 分钟重新检查签名保护。只用非个人合成色块检查全局保护，检查成功前不复制任何旅行图片。检查 / 副本失败退避 30 秒，继续走 Git。
- 副本使用 `isPrivateFile=true`；路径按仓库、分支、owner、源版本和密钥隔离。成功状态仅在实例内有界复用，没有跨用户私人照片缓存。
- 浏览器获得的链接有效 60 秒；不写入 Git、localStorage 或导出成外链。跨域读取不发送站点 Cookie 或 Referer；成功后仍使用页内 Blob / 内嵌图片供查看、拼图和作品导出。
- 软删除 / 取消发布后不再签发新链接；此前已发出的链接在剩余有效期内仍可能可用。已经下载的图片无法远程收回，这与原有浏览器页内缓存边界一致。
- 不把带 Cookie 的照片接口改成公开缓存。ImageKit 的提供商缓存由其签名保护；站点的认证响应继续 `private, no-store`。
- 保持既有 768px 缩略图和清晰展示 JPEG，不额外裁切或降质。使用 `orig-true` 分发已去元数据的文件，检查上传与分发字节一致。

## 读取与资源预算

浏览器沿用可见照片优先、前台抢占、离屏取消和共享消费者去重。CDN 首响应最多等待 2.5 秒；收到内容后按 12 秒无进展计时，正常慢传输不会因固定的短期限被误判。缩略图 / 大图总读取仍受 30 / 90 秒预算限制，用户取消不会再触发 Git 回退。连续三次加速失败后该页面 30 秒内先走 Git，避免重复等待。

作品导出仍最多两路、100 张、24MiB、失败不静默遗漏照片。本轮把单图期限调整为 45 秒、整体 120 秒，以支持弱网下两张清晰图共享带宽；超出预算仍需缩小地区 / 时间 / 相册范围，或稍后重试。不是无限后台导出。
